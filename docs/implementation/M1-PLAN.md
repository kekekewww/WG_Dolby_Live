# M1 Implementation Plan and Contracts (rev 2)

This document turns the spec (`WG_Studio_Live_Design_and_WordPress_Deployment_Spec.md`, cited as §N) into concrete contracts for the M1 build. `src/types.ts` is the TypeScript side of these contracts. When the spec and this plan disagree, the spec wins; record the deviation here.

Rev 2 applies the 60 confirmed findings of the multi-lens contract review of 2026-10-10. Finding ids are cited in brackets, e.g. [slug].

## Rev 2.1 changes

Decisions recorded after the verified code review of the committed M1 build (bc1e150):
- Account link (spec §10.4): the WooCommerce My Account page when WooCommerce is active and the page is published, else the admin `account_url` override, else null. Store follows the same order with the shop page. Contact is unchanged (override or null).
- Publishing an event requires a non-empty title and a valid start time. Otherwise the event is forced to draft with an admin notice, using the same mechanism as the slug rule.
- `scripts/seed-demo.php` refuses to run unless `wp_get_environment_type()` is `local` or `development`, or an explicit `force` argument is passed.
- `build-info.json` records `{ commit, dirty: boolean }`. `package.mjs` refuses a dirty tree unless `--allow-dirty` is given, and `check-artifact` reports a dirty build as a failure unless `--allow-dirty` is given.
- A network error while the user has paused (or after `play_blocked`) must not auto-play: the source is recovered but playback stays paused.
- Runbooks (docs only): the contact link has no automatic value and must be set during staging and production setup; permalink checks move after publishing because draft pages have no internal links; page caches must be purged after changing an event, because `/live/` and the featured card are page-load snapshots.

## 3. DOM, boot and CSS contract

### 3.1 Container

The root container is rendered by PHP:

```html
<div class="wg-live wg-live--{view}" data-wg-live-view="{view}" id="wg-live-{n}">
  <script type="application/json" class="wg-live__config">…</script>
  <noscript>…plain links to events / help / contact…</noscript>
  <div class="wg-live__sr-status" role="status" aria-atomic="true"></div>   <!-- empty; visually hidden -->
  <div class="wg-live__mount" aria-busy="true"><div class="wg-live__skeleton wg-live__skeleton--{view}"></div></div>
</div>
```

- The config is encoded with `wp_json_encode($data, JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT | JSON_UNESCAPED_UNICODE)`.
- The live region sits **outside** the `aria-busy` subtree and is empty at render time.
- After mounting, JS sets `aria-busy="false"` on `.wg-live__mount` and `data-wg-live-mounted="1"` on the root.

### 3.2 Boot timing and Elementor [elementor-hooks-before-init] [detached-instance-sweep]

- Mount timing: if `document.readyState !== 'loading'`, call `mountAll()` immediately; otherwise wait for `DOMContentLoaded`. This covers `defer` loading and delay-JS optimizers.
- Elementor wiring:
  - `wire()` checks `window.elementorFrontend?.hooks`. If it exists and a `wired` flag isn't set yet, it registers `frontend/element_ready/shortcode.default` and `frontend/element_ready/global` → `mountWithin(scope[0] ?? scope)`.
  - Call `wire()` once at boot, and again on `window` `'elementor/frontend/init'`.
  - Wrap all Elementor wiring in try/catch. It must never block mounting.
- Registry: a `WeakMap<Element, Instance>` plus a `Set<Instance>`.
  - Both `mountAll()` and `mountWithin()` start with `sweepDetached()`, which destroys every instance whose root `!isConnected`.
  - The coordinator and the poller also check `root.isConnected` on every timer tick and destroy themselves when it is false.
  - Remounting an element that is already registered is a no-op.
- `pagehide` → `stop()` on all players. `pageshow` with `persisted` → the pollers refresh immediately. Never register `unload` or `beforeunload`.

### 3.3 CSS [css-scope-check-misses-global-at-rules]

- Every selector **and every global at-rule name** is scoped.
  - The first compound selector of each comma-separated selector must contain `.wg-live`, `.wg-live-featured` or `.wg-live__*` as a whole class token. This also applies inside `@media`, `@supports` and `@container`.
  - A `+` or `~` combinator directly after the root scope compound is rejected.
  - Names of `@keyframes`, `@property`, `@counter-style`, `@layer` and `@container` must start with `wg-live-`.
  - `@font-face`, `@import`, `:root`, `html`, `body` and a bare `*` are banned.
- The authoritative check runs on the **built** CSS (postcss + postcss-selector-parser) inside `check:artifact`. `npm run lint` runs the same checker on `src/styles`, without nesting, because the sources are plain CSS.
- Class names are BEM: block `wg-live`, elements `wg-live__x`, modifiers `wg-live__x--y`. Components own their elements, and each view stylesheet targets only its own elements.
- Tokens (§3.5) are defined on `.wg-live, .wg-live-featured`. They inherit first (`inherit`, `currentColor`), then fall back to measured values. Admin overrides are added by `Assets::attach_overrides($handle)` to **every** enqueued handle (`wg-live` and `wg-live-featured`, including the late-enqueue path), scoped as `.wg-live,.wg-live-featured{--wg-accent:…}`, with each value passed through `sanitize_hex_color()` on save and again on output. [featured-style-overrides-handle]
- `.wg-live__player` (role="group", labeled) contains `.wg-live__stage`, the dark functional surface, and `.wg-live__controls` below it.
- Sizing: primary targets are at least 48×48 and secondary targets at least 44×44. Body text is 16 px and auxiliary text at least 14 px. Transitions last 160–220 ms and touch only color, opacity and small transforms. Honor `prefers-reduced-motion` and `forced-colors`.
- Headings: the theme's page title is the H1. View sections use `h2`/`h3`. The shortcode attribute `heading="h1"` (whitelist `h1|h2`, default `h2`) promotes the view title on pages where the theme title is hidden, so the title appears only once (§14.4).

### 4.2 Event fields and save rules [slug] [cpt-default-post-caps] [url-and-css-sinks] [public-event-predicate]

Meta keys are `_wg_live_{key}`. `Events::get_event_data()` returns these normalized keys:
`performers` (string[]), `description` (plain string), `starts_at_utc` (`Y-m-d\TH:i:s\Z` or ''), `display_timezone` (IANA, default `Asia/Taipei`), `status` (§6 whitelist), `media_kind` (`audio|video`), `available_modes` (a subset of `binaural|atmos`; may be empty, which the UI shows as「即將開放」), `programme` (string[]), `product_id` (int), `product_url` (string), `replay_available` (bool), `is_demo` (bool), `source_type` (`not_configured|demo`; `hls|iframe` are shown disabled and labeled "M2").

Storage format: list fields (`performers`, `programme`, `available_modes`) are native PHP arrays (`update_post_meta` serializes them). Booleans are stored as `'1'` / `'0'`. Everything else is a string or an int. `scripts/seed-demo.php` already writes this format.

`save_post_wg_live_event` rules:
- Return early when the meta-box nonce is absent (Quick Edit, REST, programmatic saves).
- Then check the nonce and `current_user_can('edit_post', $id)`, and skip autosaves and revisions.

代稱 (slug):
- Required, with a visible input in the meta box. Pre-fill it from `sanitize_title($title)` only when the title is pure ASCII.
- A `wp_insert_post_data` filter for this CPT validates the **raw** submitted value against `SLUG_PATTERN` before any `sanitize_title`. It skips `trash`, `auto-draft` and untrash.
- When the value is invalid, empty, or already used by another `wg_live_event`:
  - force `post_status` to `draft` and keep the previous `post_name`;
  - show an admin notice naming the problem;
  - never auto-suffix `-2`.

Field rules:
- Start time is entered as local time in the selected zone and stored as UTC. An invalid value keeps the old one and shows a notice.
- `source_type=demo` requires `is_demo`. Otherwise `not_configured` is stored and a notice is shown.
- `product_url` must pass `esc_url_raw( $v, ['http','https'] )`. If it doesn't, the old value is kept and a notice is shown.
- When `product_id > 0` and it names a published `product`, `productUrl` comes from `get_permalink(product_id)`. Otherwise the validated `product_url` is used, or null.
- Admin-entered URLs are re-checked on output. The bootstrap and REST responses carry the raw validated value; templates use `esc_url()`.

`Events::is_public( $p )` means `$p && post_type === POST_TYPE && post_status === 'publish' && post_password === '' && preg_match(SLUG_PATTERN, post_name)`. It is used everywhere an event is exposed: the bootstrap, both REST routes, playback, `featured_event` and the shortcode `event` attribute. A non-public event in any of those places is treated as not found. The admin list flags events whose slug is invalid.

## 5. REST API (`wg-live/v1`)

All routes are GET with `permission_callback => '__return_true'` (public data only) and strictly validated args using the shared slug pattern. `rest.root` is the output of `rest_url('wg-live/v1/')`, which can be the pretty form or the plain `?rest_route=` form. The client builds request URLs only through `restUrl()` in `util/url.ts`. [rest-root-plain-permalinks]

| Route | Response | Caching |
|---|---|---|
| `events` | `{ "events": PublicEvent[] }`. Public events only; empty when the mode is disabled. | `Cache-Control: public, max-age=30`. Never varies by user. |
| `events/(?P<slug>[a-z0-9]+(?:-[a-z0-9]+)*)` | `{ "event": PublicEvent }`, or 404 `wg_live_not_found` (also when disabled or not public). | `public, max-age=30` |
| `playback?event=<int>&mode=<binaural\|atmos>` | `PlaybackSource` | Defines `DONOTCACHEPAGE` and sends `wp_get_nocache_headers()`. |

### 5.1 Playback resolution order (server)

1. Mode `disabled` → `not_ready/disabled`.
2. `!Events::is_public(get_post($event))` → `not_ready/event_not_found`.
3. Mode not in `available_modes` → `not_ready/mode_unavailable`.
4. `Entitlement::check($event, get_current_user_id())` is not `entitled` → `not_ready/not_entitled` (for `guest` or `not_entitled`) or `not_ready/entitlement_unavailable`.
5. `!(is_demo && source_type === 'demo')` → `not_ready/source_not_configured`.
6. Non-demo event with a status not in `live|intermission` → `not_ready/event_not_playable`. Demo events skip this check: their media is public test material, and the client gates by the (simulated) status.
7. Otherwise → `{kind:'demo', url, mimeType}`, using the approved attachment for that mode or the bundled `assets/demo/demo-tone-1.mp3` (binaural) / `demo-tone-2.mp3` (atmos) with `audio/mpeg`.

### 6.3 Mode selection and start (§5.2) [gesture-start-contract]

- The two options are a radio group (`fieldset`/`legend`), side by side on desktop and stacked on narrow screens.
- The §5.2 strings are pinned verbatim, including the action labels「選擇耳機模式」and「選擇家庭劇院模式」, which are part of each option's accessible label.
- The primary button is「開始聆聽」.
- Preselection: `?wg_mode=` applies only when it is valid and in `availableModes`; otherwise the remembered `localStorage['wg-live:mode']` applies. Never auto-start and never store entitlement.
- **Prefetch** the descriptor (JSON only, no media) whenever `selectedMode` becomes non-null, including a preselection at mount.
- **Start invariant**: `start()` runs `destroy(old)` → `adapter.load(source)` → `adapter.play()` **synchronously** inside the click handler, with no `await` before `play()`. `load()` assigns the source synchronously, and its promise only reports readiness.
- When `play()` rejects with `NotAllowedError`, the status becomes `paused` with error `play_blocked` and the UI shows「請點擊開始聆聽」. Its button calls `adapter.play()` directly, with no new resolve and no automatic retry.
- The switch flow prefetches the other mode's descriptor when the dialog opens. The confirm button's click handler calls `switchMode()` synchronously, and that path relies on the shared element having been unlocked by the earlier gesture-initiated `play()` (D9).

### 6.4 Transitions [state-transition-table-missing] [status-change-during-playback] [f06-shared-element-stale-signals]

User actions:
- `start`, `togglePlay`, `stop`, `switchMode`, `retry` and `reloadLastGood` each bump `requestId` and abort the previous AbortController. Async results carrying an older id are dropped.
- Pause is unavailable while the status is `loading` or `switching`.

An `AbortError` from `play()` is benign. It produces no PlayerError and no retry, and the state follows the action that interrupted it.

Adapter events to player state:

| Event | Effect |
|---|---|
| `playing` | `status=playing`, `activeMode=loadedMode`, `confirmedPlaying=true`, `lastGoodMode=activeMode`. Resets the retry budget only after 30 s of continuous playback. |
| `paused`, from outside the player (lock screen, headset) | `paused`. Ignored while `loading` or `switching`. |
| `waiting` | grace timer, see §6.5 |
| `ended` | Demo sources loop. For any other source → `paused`, `confirmedPlaying=false`. |
| `error` | classify per §6.5 |

`destroy()` removes its listeners **before** calling `pause()`, `removeAttribute('src')` and `load()`.

Event-status changes after mount, from the poller or the dev panel:

| Change | Effect |
|---|---|
| → `ended` / `cancelled` | `stop()`, close any open switch dialog, show the gate copy |
| → `scheduled` / `doors_open` while loading or playing | `stop()`, disable Start, keep `selectedMode` |
| `live` ↔ `intermission` | no adapter change |
| `doors_open` → `live` | enable Start, with no auto-start |
| dev panel `setEventStatus(null)` | re-run these rules against the real status |

`stop()`:
- bumps `requestId`, aborts fetches and clears **all** coordinator timers;
- destroys the adapter and resets the element;
- sets `status` to `selecting` when `selectedMode` is set, otherwise `idle`;
- clears `activeMode`, `confirmedPlaying` and `retry`, and keeps `selectedMode`.

### 6.5 Errors, retries and the watchdog [media-error-classification] [stall-watchdog-retry-ownership]

Classification is done in one place and keyed by `requestId`, so a media `error` event and a `play()` rejection count once.

| Signal | Code | Retried? |
|---|---|---|
| `canPlayType(mimeType) === ''` before load | `unsupported` | no |
| `navigator.onLine === false` at failure | `network` | yes (and retry early on `online`) |
| MediaError 2 | `network` | yes |
| MediaError 3 | `decode` | no |
| MediaError 4 or `play()` NotSupportedError while `readyState === HAVE_NOTHING` after a non-empty `canPlayType` | `network` (fetch failed) | yes |
| MediaError 4 after metadata loaded | `unsupported` | no |
| `play()` NotAllowedError | `play_blocked` | no (user action) |
| `play()` AbortError | benign | — |
| Server `not_ready` | per §6.7 | no |

- Retries cover only `network`: at most 3 automatic retries, after 2 s, 5 s and 10 s. After that the status is `failed` and only a manual retry is offered.
- Watchdog timers, all owned by the coordinator:
  - load timeout 20 s;
  - while play is intended (`loading`, `playing`, `reconnecting`, `switching`), no `currentTime` progress for 3 s → `reconnecting` (announced after the grace period), and no progress for 15 s → `network` error, which consumes one retry;
  - the watchdog is never armed while `paused` or after `play_blocked`.
- `stalled` is a hint only.
- `fatal:false` from a library is tolerated for up to 15 s.
- Mode switches never happen automatically on failure. When Atmos fails, the UI offers「改用耳機 Binaural」.
- Public error codes are generic, e.g. `E-NET-01`. They never contain URLs or stacks.

### 6.6 Switch dialog and focus [dialog-focus-return]

- Do not use `returnValue`. Escape or cancel only closes the dialog. Confirm calls `switchMode(mode)` and then `dialog.close()`.
- During `switching`, the「切換模式」trigger gets `aria-disabled="true"` plus a click guard, never `disabled`. Nodes keep a stable identity across renders, so components update in place.
- After closing, and again after the switching render settles, focus goes to the trigger when it is connected and focusable, otherwise to the player status heading (`tabindex="-1"`).
- The dialog text names the current mode and the other mode, and says that switching may interrupt playback briefly.
- A failed switch leaves `lastGoodMode` in place and offers「重新載入〈舊模式〉」. When the failed mode was Atmos it also offers「改用耳機 Binaural」. The track is never changed silently.

### 6.9 HLS and iframe in M1 [hls-path-selection] [iframe-adapter-policy]

In M1, the server never emits `hls` or `iframe`, and the coordinator treats them as `not_configured`. The `hls.ts` and `iframe.ts` stubs implement the adapter interface and do nothing, so they never report `unsupported` for an unknown case (§9.4).

M2 contract, recorded now:
- **HLS**: use native HLS only when `canPlayType` is non-empty and `'ManagedMediaSource' in window`. Otherwise use the plugin's own pinned, lazily loaded hls.js gated by `Hls.isSupported()`, never `window.Hls`.
- **iframe**: the client asserts https and `new URL(url).origin === allowedOrigin`. Messages require `origin === allowedOrigin`, `source === frame.contentWindow` and a valid schema. Send with `postMessage(msg, allowedOrigin)`. Record `allow`/`sandbox` values per vendor once tested.

### 6.10 Labels, capabilities, keyboard, announcements

Capabilities [ios-volume-fake-control] [capabilities-static-ios-volume]:

- Adapter capabilities are per instance and final after `load()` resolves. The coordinator copies them into the state after each load.

Keyboard [space-shortcut-scope]:
- One keydown listener sits on `.wg-live__player`.
- Ignore the event when it is `defaultPrevented` or `repeat`, during `isComposing`, or with any modifier key.
- Ignore it in editable targets.
- For Space, also ignore it on activatable controls (`button`, `a[href]`, `summary`, `[role=button|switch|slider]`).
- Space and K toggle playback, and `preventDefault` runs only when the shortcut was handled.
- Document the shortcuts in Help and in `aria-keyshortcuts`.

Announcements [live-region-strategy]:
- Use only `.wg-live__sr-status`, and announce only when `selectAnnouncement(state)` returns something new.
- Coalesce within 750 ms, except `play_blocked` and failures, which are announced immediately.
- Announce: loading started, playing confirmed, paused, reconnecting (after the grace period), failed, switch success or failure, and event-status changes.
- Never announce the countdown, the retry counter or the time display.

Featured card (`templates/featured.php`):
- the poster with width and height
- the title, with the「介面示範」badge when it is a demo
- time with the zone
- a short text, trimmed to 80 characters

There is no player and no autoplay. With no featured event:「線上音樂會資訊即將公布」plus a link to Live. When disabled: the text only.

### Pinning WordPress and PHP (note for tooling)

`.wp-env.json` must pin `"core"` (for example `"WordPress/WordPress#<version>"`) and `"phpVersion"`. Until the §3.1 inventory, use a recorded known-good pair; afterwards re-pin to production and make `npm run lint:php` cover that PHP version. The default wp-env environment is not equivalent to production.
