# HANDOVER：M1 交接文件（模板）

依據：規格 §20（四組分開列出）、§19（最終驗收與交付清單）、§18.2（日常操作）。

使用方式：交接時複製這個檔案並填寫。**四組不能混寫**：

- **已實作**：程式與文件已寫好、在 repository 裡。
- **已測試**：有測試紀錄支持（自動化或人工），寫明在哪個環境、哪個版本、結果與證據位置。
- **已部署**：實際在 staging 或正式站上線，寫明環境、日期、ZIP SHA-256。
- **尚待外部條件**：缺少外部資料、授權、設備或決定，因而無法完成的項目。

規則：不能把計畫寫成已完成的操作；沒做的就寫「未執行」；不得寫成「付費直播已安全上線」。M1 的完成定義是：錄音室管理者能在既有 WordPress 後台管理活動；觀眾能從原站入口進入同風格的完整示範體驗；開發者能重現建置、部署與回復，並清楚區分尚未接入的正式直播能力（規格 §19.4）。

## 6. 管理者日常操作（規格 §18.2）

建立活動 → 填寫時間／演出者／海報 → 設定示範或待開放 → 選擇可用聆聽模式 → 預覽手機與桌面 → 選為首頁精選 → 發布活動資訊。

- 每場活動的**代稱（slug）**必填，格式為小寫英數與連字號（`^[a-z0-9]+(?:-[a-z0-9]+)*$`），不要用中文標題衍生。代稱留空、重複或格式錯誤時，活動會停在草稿並顯示提示。
- 演出狀態可由管理者調整。只有播放頁輪詢活動狀態（合理間隔，失敗時退避，不是每秒請求；倒數在瀏覽器端更新，真實狀態以後端資料為準）。`/live/` 活動列表與首頁精選卡是頁面載入時的快照。
- 修改活動的狀態、時間或取消後，清除 `/live/`、`/live/<播放頁>/` 與首頁的頁面快取（或等快取過期），否則這些頁面會繼續顯示舊的徽章、按鈕與取消訊息。
- 發布活動需要標題與有效的開始時間；缺少任一項時，活動會停在草稿並顯示提示。
- 活動結束後，回放是否開放需由錄音室確認。沒有回放時仍保留活動紀錄與結束訊息，不顯示無效播放連結。
- 家庭劇院相容表：沒有真實測試紀錄的列維持「尚待測試」。標為「已驗證」需同時填測試日期、裝置、OS、瀏覽器與輸出路徑。
- 緊急關閉：設定頁部署模式改 `disabled`（見 [ROLLBACK.md](ROLLBACK.md)）。
