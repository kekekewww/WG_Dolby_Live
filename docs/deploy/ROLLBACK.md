# ROLLBACK：回復

依據：規格 §18.1、§15.2、M1-PLAN §7.5。適用於 staging 與正式站。

只回復**這次修改**的東西：外掛、三個頁面、首頁區塊、選單項目、外掛設定。**不用舊的整份資料庫覆蓋正在產生新訂單的網站**（第 6 節）。

## 1. 順序總覽

由輕到重，**能在前面步驟解決就不要往後**：

| 步驟 | 動作 | 影響 | 何時用 |
|---|---|---|---|
| A | 部署模式切到 `disabled` | 活動資料、播放、首頁區塊內容全部變成「尚未開放」，不需要刪任何東西 | 任何公開問題的**第一步** |
| B | 暫時撤回三個頁面（改回草稿） | 前台不再有 Live 頁面 | 頁面本身有問題 |
| C | 移除首頁 `[wg_live_featured]` 區塊與選單 `Live` 項目 | 前台不再有入口 | **停用外掛之前必做** |
| D | 停用 `wg-live`，必要時還原上一版已測試的 ZIP | 外掛完全不執行 | 影響全站功能 |
| E | 完整資料庫回復 | 影響所有資料 | 只有管理者確認資料差異後才考慮 |

> **為什麼 C 一定要在 D 之前：** 外掛停用後，WordPress 不再認得 `[wg_live …]` 與 `[wg_live_featured]`，頁面會把原始 shortcode 文字直接印給訪客。先移除或撤回這些出現位置，再停用。

## 2. 步驟 A、B：關閉公開入口

### A. 切回 disabled（先做這個）

1. 後台 → Live 活動 → Settings，部署模式選 `disabled`，儲存。
2. 效果（M1-PLAN D16）：活動清單為空、單一活動請求回傳 404、播放請求回傳「尚未開放」、頁面載入後顯示「線上音樂會尚未開放」並附首頁與聯絡連結；首頁區塊顯示「線上音樂會資訊即將公布」且沒有按鈕；說明頁仍可用。
3. 驗證（登出視窗）：
   - `/wp-json/wg-live/v1/events` 回傳空的 `events`。
   - `/live/` 顯示「線上音樂會尚未開放」。
   - 清除頁面快取後再看一次，確認不是舊快取。
4. 記錄時間點與操作者。

### B. 暫時撤回新頁面

若頁面本身有問題（版面、重複頁首、內容錯誤）：

1. 將 `Live`、`Listen`、`Listening Guide` 三頁改回**草稿**（或設為私人）。
2. 清除快取。登出視窗開三個網址，應該不再公開。
3. 此時選單與首頁若還有入口，會連到不存在的頁面——立刻做步驟 C。

## 3. 步驟 C：只回復這次改動的首頁區塊、選單與外掛設定

**停用外掛前一定要做完這一節。**

### 3.1 移除首頁 Live 區塊

1. Elementor 開啟首頁。
2. 兩種方式擇一：
   - 刪除含 `[wg_live_featured]` 的 Live 容器，更新。
   - 或到 History → Revisions，載入 [NAV-HOMEPAGE.md](NAV-HOMEPAGE.md) 第 3.1 節記錄的**部署前版本**，更新。載入前先確認該版本之後沒有別人做過無關的修改。
3. 清除首頁快取，登出視窗確認首頁不再有 Live 區塊、沒有原始 `[wg_live_featured]` 文字。
4. 與部署前截圖比對首頁其他章節。

### 3.2 移除選單項目

1. 外觀 → 選單，選到當初加入 Live 的那份選單。
2. 移除 `Live` 項目（只移除選單項目，不是刪除頁面）。儲存。
3. 桌面與手機各檢查一次：其他項目順序、Store 子選單、Logo 與首頁項目都和部署前一致。**不要重新指派選單位置。**

### 3.3 回復外掛設定

- 設定頁的內容（綁定的 Page ID、精選活動、Account／Store／Contact 覆寫、FAQ、相容表）在停用外掛時**會保留**，不需要手動清除。
- 若這次部署要把設定還原成上一版的值，依 [DEPLOY-RECORD.md](DEPLOY-RECORD.md) 的「設定快照」逐欄改回，儲存後「部署資訊」的設定版本號會增加，這是正常的。
- 示範活動要不要保留由管理者決定；停用不會刪除活動與頁面。

### 3.4 其他入口

商品說明裡若加了「活動資訊與聆聽說明」連結，一併移除。不修改購買按鈕、價格、付款流程與訂單狀態。

## 4. 步驟 D：停用外掛並還原上一版

前提：已完成第 2、3 節（模式 `disabled`、頁面撤回、首頁區塊與選單項目移除）。

1. 後台 → 外掛 → 停用 `wg-live`。停用不刪除活動與頁面，也不改變任何選單或首頁。
2. 若需要回到上一版：
   1. 取得 [DEPLOY-RECORD.md](DEPLOY-RECORD.md) 記錄的上一版 ZIP，並**驗證它的 SHA-256**（`sha256sum -c` 或 PowerShell `Get-FileHash`）。
   2. 外掛 → 安裝外掛 → 上傳外掛，選上一版 ZIP。WordPress 發現已存在同名外掛時，選「以上傳的版本取代目前版本」。
   3. 啟用，確認「部署資訊」顯示上一版的版本與 build SHA-256，部署模式是 `disabled`。
   4. 確認設定仍在，再依需要逐步重新開啟。
3. 若這是**首次部署**，沒有上一版：停用即可。**不要按「刪除」**，除非先確認第 7 節的解除安裝設定。
4. 清除頁面快取與 CSS／JS 最佳化快取。
5. 做第 8 節的回復後檢查。

## 5. 後台無法使用時的緊急做法

外掛造成全站致命錯誤、後台也進不去時：

1. 以 SFTP 或主機檔案管理員，把 `wp-content/plugins/wg-live` 資料夾**改名**（例如 `wg-live.disabled`）。WordPress 找不到外掛檔案，會自動停用它。若有 WP-CLI，可以執行 `wp plugin deactivate wg-live`。
2. 原站恢復後，訪客可能暫時看到頁面上殘留的原始 shortcode 文字（因為步驟 C 還沒做）。立刻登入後台，依第 2、3 節撤回頁面、移除首頁區塊與選單項目。
3. 之後再決定：還原上一版 ZIP（第 4 節）或在 staging 修正後重新部署。
4. 不要為了趕時間直接用備份覆蓋整個站。

## 6. 資料庫回復（步驟 E）

- **預設不做。** 正式站持續新增訂單與會員，用舊的整份資料庫覆蓋會讓這些資料消失。
- 只有在管理者**確認資料差異與還原影響後**，才考慮完整資料庫回復。至少先確認：
  - 備份時間點之後新增了哪些訂單、會員、留言與設定變更。
  - 那些資料如何保留或補回。
  - 回復負責人與管理者的書面同意（姓名、時間）。
- 能用步驟 A–D 解決的，一律用步驟 A–D。回復核可記錄寫進部署紀錄。

## 7. 停用與解除安裝對資料的影響

| 動作 | 對內容的影響 |
|---|---|
| 停用外掛 | 不刪除活動、頁面、設定。 |
| 刪除（解除安裝）外掛，預設設定 | **不刪除**活動、頁面、設定；也不動附件、頁面、使用者、商品與訂單。 |
| 刪除外掛，且設定頁勾選了「解除安裝時刪除資料」 | 只刪除本外掛的資料：所有 `wg_live_event`（含垃圾桶中的）及其 `_wg_live_*` 欄位、兩個設定選項、示範音訊核可標記。**仍不刪除**附件、頁面、使用者、商品與訂單。 |

刪除外掛前，先打開設定頁確認該選項**未勾選**（除非管理者明確要求清除本外掛資料）。這是需要管理者明確執行的操作，不是回復流程的一部分。

## 9. 記錄

把回復的原因、時間、做了哪些步驟、還原到哪個版本（含 ZIP SHA-256）、尚待處理的項目，寫進新的一份 [DEPLOY-RECORD.md](DEPLOY-RECORD.md)（記錄類型選「回復」）。紀錄中不放主機帳密，也不放完整私有串流網址。
