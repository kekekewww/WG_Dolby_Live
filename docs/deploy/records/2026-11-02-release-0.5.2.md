### 已實作 (implemented)

- Before 0.5.2, on Safari (which can decode Dolby Atmos) 開始聆聽 failed with 「播放失敗」 because an http stream cannot load inside the https page; the listener then had to use 取得我的播放連結 → 在新分頁開啟.
- Now `opensInBrowserPlayer()` (`src/adapters/hls.ts`) says yes when the source is hls, the link is http on an https page, the browser plays HLS itself (`chooseHlsPath` = native: Safari 17+, iOS 17.1+, older iOS without MSE) and does not refuse E-AC-3. Then `start()` (`src/state/coordinator.ts`) hands the cached, ticket-checked link to the view inside the click and attaches nothing; the view opens the link in the same tab (`window.location.assign`), which is what opening the link does. Feature detection only.
- Unchanged: Chrome, Edge, Firefox and Windows (hls.js path) keep the VLC link panel; an https link plays in the page; the server still checks the ticket before handing out any link; the link is never part of public data.
- Not covered: Safari 16 and older on Mac (MediaSource, no ManagedMediaSource) take the hls.js path and keep the 0.5.1 behaviour (link panel after the failure).
